HEAT MAP FILTER, CACHE, COORDINATE AND DUPLICATE CLEANUP FIX

1. Back up the working project.
2. Extract this ZIP into the project root.
3. Allow the included app files to replace the matching files.
4. Commit and push the changes to deploy on Render.
5. After deployment, open the Heat Map page and import the completed workbook once.

No database migration is required.

What this fixes:
- The Heat Map JavaScript now uses a versioned URL, preventing browsers from keeping an old cached filter script.
- Category and province dropdowns respond explicitly to selection changes.
- Selecting Deceased, Next of Kin, Church, Cemetery, Crematorium or Insurance Clients filters the totals, table and map.
- Blank Latitude/Longitude values are no longer treated as coordinates 0,0.
- Existing repeated database imports are collapsed automatically during the next valid import.
- Duplicate cleanup is scoped to the selected franchise and category.
- The oldest record is retained while useful newer duplicate details are merged into it.
- Unrelated existing records remain untouched.
- The uploaded file is then merged: new records are added, changed matches are updated and unchanged repeats are skipped.
- The import message reports how many existing duplicates were removed.

Important workbook finding:
- The supplied workbook contains 162 data rows and 162 unique MF Files; it does not contain duplicate MF Files.
- Its Latitude/Longitude blocks are blank. These records should appear as Unmapped until coordinates are added or Geocode Missing is run by an authorised user.
